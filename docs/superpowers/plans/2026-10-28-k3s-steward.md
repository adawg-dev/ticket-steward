# Ticket Steward on k3s Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the steward on k3s as an event-driven dispatcher that launches one pod per run, where the agent container holds no credential and sidecars put credentials on its requests.

**Architecture:** Every run (implement, fix, chat) is split at one seam: the dispatcher *prepares* a `RunSpec` (it holds Linear/GitLab access and the DB), an executor *executes* it, and the dispatcher *finishes* from the `RunReport`. A `LocalExecutor` runs the execute half in-process (today's behaviour, the Compose host, all existing tests). A `KubernetesExecutor` runs it as a Job whose pod has an agent container with no credentials, plus keyproxy, tools, egress, Postgres/Redis/RabbitMQ and session-sync sidecars. Secrets come from AWS Secrets Manager through the pod's k3s service-account token, and sessions live in MinIO.

**Tech Stack:** TypeScript ESM on Node 24, Fastify, better-sqlite3, zod 4, Claude Agent SDK, `@kubernetes/client-node`, `@aws-sdk/client-secrets-manager`, `@aws-sdk/client-s3`, `@aws-sdk/client-sts`, `@aws-sdk/credential-providers`, mitmproxy (egress sidecar, Python addon), MinIO, kustomize manifests.

**Spec:** `docs/superpowers/specs/2026-10-28-k3s-steward-design.md`

## Global Constraints

- Branch `feat/k3s` from `feat/container-chat`. The Compose host keeps working on `LocalExecutor` throughout; nothing here changes the live deployment until the cut-over task.
- The agent container gets **no** credential: no `DEV_` value, no service-account token (`automountServiceAccountToken: false`, no projected token volume mounted into it), no model key, no tools token, no MinIO credential. Only the runner token (report-only) is in its env.
- No long-lived credential anywhere new: no AWS keys, no MinIO access keys in pods, run tokens revoked when the run finishes.
- Secret values are read like `kickoff/infra/script/preview.py` `fetch_secrets`: JSON object → its first value as a string; otherwise the raw string; missing or empty is an error naming the secret id, never the value.
- Projected token audiences: `sts.amazonaws.com` for AWS, `minio` for MinIO. Token expiry 3600 s.
- Fixed in-pod paths, so existing sessions resume: worktree `/var/lib/ticket-steward/work/ticket-<KEY>`, `CLAUDE_CONFIG_DIR=/var/lib/ticket-steward/sessions`, artifacts `/var/lib/ticket-steward/jobs/<jobId>/artifacts`.
- Fixed in-pod service ports: Postgres 5432, Redis 6379, RabbitMQ 5672, keyproxy 4180, tools 4181, egress 4182, agent check endpoint 4183, app port 3000.
- Dispatcher ports: 3020 public (webhooks, `/health`), 3021 cluster-internal (run callbacks), 3022 `127.0.0.1` only (admin API).
- Claude Code brain only on the Kubernetes runtime; config load refuses `openai-agents` there.
- Never typecast to `any`. Run `npm run typecheck`, `npm run lint`, `npm test` before every commit.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push.

## Review Focus

- A real secret value echoed back in an API response (an "invalid key sk_test_…" error body) must reach the agent as its placeholder, never the real value (Task 9).
- A placeholder sent to a host outside its allowlist goes out unchanged and is logged; the real value never leaves for that host, including inside Basic auth (Task 9).
- The dispatcher restarting while run pods are live must reattach to them, not requeue and double-run (Task 12).
- Agent-written worktree config (`core.fsmonitor`, `url.<x>.insteadOf`, `http.proxy`, filters) must not execute or redirect anything in the tools sidecar, whose push still lands on the configured remote (Task 6).
- A run pod killed mid-run (SIGTERM, eviction) still uploads its session before exit, and a first run with no stored session starts cleanly (Task 10).
